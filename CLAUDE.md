# Inkoly Quiz — правила проєкту

Онлайн-платформа для домашніх квізів: ведучий з планшета, загальний екран на ТВ,
учасники з телефонів. Повна специфікація — PRD v2.2 (`docs/PRD.md`, ще не доданий у репозиторій),
контракт бекенд↔фронтенд — `docs/contract.md`.

## Правила, які не обговорюються

1. **Клієнт ніколи не пише в таблиці гри напряму.** Приєднання, відправлення
   відповіді, зміна стану кімнати — тільки через серверні функції з підвищеними
   правами, які самі перевіряють роль, час і належність до кімнати (PRD §4.9).

2. **Оцінювання тільки на сервері.** Інакше правильна відповідь має потрапити
   в браузер учасника — а вона не потрапляє туди ніколи (§8.3). Учасники
   читають санітизований зріз варіантів без ознаки правильності.

3. **Роль користувача живе в `app_metadata`, не в `user_metadata`** (§2.4).
   `user_metadata` редагується клієнтським SDK напряму. Перевірка ролі
   на клієнті — це навігація, а не безпека.

4. **Сервер — єдине джерело часу** (§8.2). Клієнт лише відображає відлік
   до серверного дедлайну, з поправкою на зсув власного годинника
   (`useServerClock`).

5. **Жодного вшитого тексту в компонентах.** Усі рядки через ключі перекладу,
   навіть при одному словнику (§4.6, критерій приймання §17.20).

6. **Схема змінюється тільки міграціями.** Studio — для читання. Регенерація
   типів (`npm run db:types`) — у тому самому коміті, що й міграція;
   це перевіряє pre-commit хук.

7. **Enum містять повний перелік запланованих значень**, включно
   з нереалізованими (§4.1). Джерело — `app/types/game.ts`; значення в базі
   мають збігатися.

## Структура

```
app/
  assets/styles/    токени як CSS-змінні (§4.7), міксини доступні в кожному <style>
  composables/      useDb, useServerClock
  constants/        ліміти і набір аватарів — інваріанти під тестом
  middleware/       role.ts — гард /admin, НЕ безпека
  pages/            маршрути §10.4
  plugins/          realtime.client.ts — канал на рівні застосунку, не компонента
  stores/           auth, editor, room, realtime, ui (§10.5)
  types/            game.ts (enum), answers.ts (payload), database.generated.ts
supabase/           міграції, політики, серверні функції
docs/contract.md    контракт між двома розробниками
test/               unit-тести інваріантів
```

## Команди

```bash
npm run dev          # dev-сервер
npm run lint         # ESLint
npm run typecheck    # vue-tsc
npm test             # vitest
npm run generate     # статична збірка (SPA, SSR вимкнено)
npm run db:start     # локальна Supabase в Docker
npm run db:types     # регенерація типів після міграції
```

## Коміти

Conventional Commits, скоупи: `app`, `db`, `auth`, `editor`, `host`, `screen`,
`play`, `realtime`, `i18n`, `ci`, `deps`. Перевіряється commitlint.
